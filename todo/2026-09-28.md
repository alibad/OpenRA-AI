# 2026-09-28

## In-game faction catalog and companion catalog answers

### What We Built

- The shared catalog now reaches the native game and the companion, not just
  the web. The engine's new **Faction Catalog** screen (Main menu > Factions,
  and "Open in Faction Catalog" on a faction pack in Factions & Capabilities)
  lists only the factions available in the loaded mode:
  - Classic: China, Iran, Türkiye, Saudi Arabia and Yemen, plus the five
    original countries;
  - RA2: China, Iran and Türkiye, plus the nine original countries, with the
    note "Classic only: Saudi Arabia, Yemen".
- Each faction shows its signature units, doctrine and summary, and a roster
  grouped by domain with the real production icons. Unit details are read from
  the loaded rules, and "More on the web"/"Unit on the web" open the
  `https://rtsai.net/factions|units/{id}?mode=` pages.
  `docs/in-game-catalog.md` has the details.
- `catalog/factions.json` gains an additive `links` object with the public
  origin and the faction/unit route templates. `content_catalog.py` validates
  the templates and every link built for an implemented faction mode or unit
  variant.
- `scripts/prepare-ra2.py` adds the engine's catalog chrome and messages to the
  integrated RA2 manifest, but only when the engine ships them, so older pinned
  engines package unchanged.
- Companion:
  - The game posts its rules digest to `POST /v1/factions/live` from the main
    menu, the catalog and the in-match HUD. `faction_catalog.py` joins it to the
    catalog.
  - Questions that name factions or units get deterministic, mode-scoped
    answers before any model call. Examples: "What does the Qilin counter?" and
    "Which Yemen unit is anti-air?". In RA2 the latter answers "Yemen isn't
    available in Red Alert 2 mode yet. It is available in Classic."
  - `ask()` receives mode-filtered catalog facts. The planner gets a
    `faction_catalog` MCP tool (29 tools).
  - Orders, advice and live-state questions still reach the planner.
- New checks:
  - `scripts/validate-faction-catalog.py` checks Classic and data-only RA2
    against the engine's merged rules.
  - `scripts/verify-catalog-package-layout.py` checks the staged Windows and
    macOS layouts; `--launch-game` renders the catalog from the Windows layout.
  - `scripts/verify-companion-catalog-live.py` runs a live headless game with a
    private companion.

### What We Fixed

- The consistency check found Saudi Arabia's fixed-wing airfield (`SAFLD`),
  which only Saudi Arabia can build, missing from its faction roster. The
  engine's Classic Experience roster now lists it.

### Key Decisions

- Every number comes from the engine's loaded rules, never from the catalog.
  The catalog stays editorial: story, roles, signature units, counterplay,
  availability per mode, and links.
- Modern-faction rosters come from the Experience faction packs, plus any actor
  that only that faction can build. Original countries use every actor they
  can build under the loaded rules, and the actors unique to a country are
  marked.
- Link templates live in the catalog, so the game, companion and validator
  share one source. The existing schema stays at version 1, and the
  availability fields `ra2-red-sea` owns are untouched.
- Companion answers never quote statistics for a faction or unit unavailable in
  the mode under discussion. The digest carries no match state, so answers are
  identical with or without a live snapshot and cannot reveal fogged state.
- Preserved faction behavior: a faction that appears in RA2 later (a pack plus
  a catalog status flip) shows up with no code change. Flipping the status
  without the pack, or adding the pack without updating the catalog, fails the
  validator.

### Verification

- Validator: Classic is valid with 10 factions and RA2 with 12 (0 issues each).
  Mutated catalogs fail with the expected codes: missing, foreign or leaking
  actors, malformed links, and premature RA2 availability.
- Tests:
  - 16 product tests pass: `tests/test_faction_catalog_validation.py` (12) and
    `tests/test_content_catalog.py` (4), with
    `OPENRA_AI_ENGINE_ROOT=../OpenRA-wt-in-game-catalog`.
  - The companion suite passes: 279 tests, 3 environment skips, including 16
    new catalog tests.
  - Companion evals: 2 pre-existing mission-corpus failures that depend on
    generated missions absent from a fresh worktree.
- Package layouts: the staged Windows (`<root>/engine/openra` →
  `<root>/catalog`) and macOS (`Resources` → `Resources/catalog`) layouts both
  resolve the staged catalog. That holds for the engine, with no catalog path
  given, and for the packaged companion, via the frozen executable and
  `OPENRA_AI_ENGINE_DIR`. A native run from the Windows layout rendered the
  marked staged catalog.
- Live: headless Classic and RA2 games posted their main-menu digests to a
  private companion, which answered each mode's questions with source
  `faction-catalog`. A Classic match republished its map rules from the HUD
  (`source=match`).
- Screenshots were reviewed for both modes at 1280×720 and 1920×1080: roster
  icons, stats, tooltips, no overflow, the main-menu entry and the Factions &
  Capabilities link. Evidence is in `artifacts/in-game-catalog-screenshots/`
  and `artifacts/catalog-package-layout/`.
- Engine: zero-warning Release build and 576 tests passed with 2 skipped
  (the 544 baseline plus 32 new).
- Lint parity: the warning multisets match a detached engine `main` for
  Classic `world-war-iii` (2 warnings), `ai-assistant-only` (193 warnings plus
  the same pre-existing error), RA2 all-map (795), TS (135) and D2K (128).
